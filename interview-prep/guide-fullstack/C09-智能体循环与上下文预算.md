# C09 智能体循环与上下文预算：让模型会行动但不越界

> 课程性质：核心；目标掌握：看懂链路、理解机制、设计与表达。
> 课程导航：[导学](../WeKnora/导学.md)；前置：[C01 身份与租户边界](C01-身份与租户边界.md)、[C08 动态问答流水线](C08-动态问答流水线.md)；上一课：[C08](C08-动态问答流水线.md)；下一课：[C10 Wiki 持久任务与恢复](C10-Wiki持久任务与恢复.md)。
> 对应：B6、B2；[面经 Q6](../WeKnora/面经.md#q6-智能体连续执行时如何约束上下文与工具调用的权限)、[面经 Q2](../WeKnora/面经.md#q2-如何让普通页面与嵌入页面显示受保护内容但不混淆权限)。源码基线：`d06733d4157736c0e0e7972d014f0f056d237bb0`。

## 本课重点

与 C08 的固定问答阶段不同，智能体每轮由模型决定继续调用哪些工具还是给出答案，`think → analyze → act → observe` 可重复多轮。问题不是简单“让模型调用函数”：历史和工具结果会填满模型上下文，输出截断可能使工具 JSON 参数不完整，共享 Agent 的来源租户不能被误当成用户的无限读取许可，并发读工具与修改工具需要顺序屏障。实现分别用持久会话历史、窗口压缩和断点、模型输出校验、受限工具授权以及有界迭代处理这些风险。

## 主链与职责

`AgentQA(会话和 CustomAgent) → 解析租户/模型/工具范围及历史预算 → 从 DB 恢复多轮消息与压缩 checkpoint → AgentEngine.executeLoop → 每轮预估上下文并压缩旧历史 → LLM(function calling) → 分析停止/工具请求 → 串行或并发受控执行工具 → 将结果写回消息 → 下一轮或最终答案事件`。会话服务配置 Agent、记忆/沙箱与模型；AgentEngine 控制轮次、模型调用和状态机；工具注册表只暴露配置、能力与权限允许的工具；共享资源 `access` 约束 KB 读写；事件总线负责回传思考、工具、答案/错误。工具返回仍要经 `observe` 加入下一轮模型消息，才形成闭环。

## 源码阅读

1. [入口：`AgentQA`](../../internal/application/service/session_agent_qa.go)：要求 `CustomAgent`，被委派会话还要校验 scheduler 所有权；用共享资源租户解析 KB/模型配置，但在构建配置后另设访问级别与授权作用域。模型元数据的 `ContextWindow` 经 `AgentMaxContextTokens` 算实际窗口，输出限制另算；`MultiTurnEnabled` 时以 `HistoryTokenBudget` 调 [历史加载器 `LoadAgentHistory`](../../internal/application/service/agent_history.go) 从数据库游标读取已完成的会话轮次、压缩 checkpoint 和工具调用/返回，超预算丢较旧轮次；不开多轮则上下文为空。历史读取失败会记录警告并以空历史继续，不能说“在内存中永久保留上一轮”。
2. [循环：`executeLoop/runReActIteration`](../../internal/agent/engine.go)：按 `MaxIterations` 上限运行，进入每轮先看 `ctx.Done()`，有工具结果时尝试挽救已有内容但仍返回取消错误；刷新 MCP 工具定义只在上一批工具执行结束的轮次边界。每轮先 `estimateCurrentTokens` 和 `manageContextWindow`，再接收用户 mid-run steering/协作消息，调用带重试的 LLM。若响应真正触及上下文窗口，`forceCompaction` 并**整轮只强制重试一次**；预算耗尽且未取消/挂起时才合成兜底答案。空内容停止和重复截断亦有额外保护，不等同模型返回 stop 就一定是成功答案。
3. [上下文：`manageContextWindow/runCompaction`](../../internal/agent/observe.go) 与 [压缩设置](../../internal/agent/compaction/settings.go)：超阈值先总结旧消息并保留最近窗口；一次压缩要释放至少 `TokensBefore/20` 即约 **5%** 才更新当前消息，否则记录耗尽尺寸，不在相同消息数量上反复为无收益总结付费。即使当前压缩释放不足，若生成了 checkpoint 仍存库，避免下轮重复总结；有效压缩重置旧 token usage 基线。若较新尾部的大工具输出压不掉，最后退化为有损裁剪，不把工具输出无限堆给模型。阈值、窗口和预留量读取 `Settings`，不是随口说“固定到 8K token 就压”。
4. [执行工具：`executeToolCalls/executeToolCallsParallel`](../../internal/agent/act.go)：模型响应若因输出 token 上限被截断，**全部**可疑工具调用均不执行，逐一写失败结果请求模型重新给完整 JSON，避免把半个写操作当成功。允许并发且一次出现多个工具时仅对 `CanRunConcurrently` 的读型调用以 `errgroup.SetLimit(8)` 并发；写操作等前面的读完成再执行，后面的读等写完成，结果按模型原始顺序入 `step.ToolCalls` 并发事件；提示用户的工具可挂起轮次并停止后续调用。普通串行模式逐个执行。
5. [安全边界：`WithSharedAgent/HasKBGrant`](../../internal/application/access/context.go)：共享 Agent 获授权后，把执行租户设为 Agent 的来源租户便于访问模型和数据，但读授权只覆盖 Agent 配置的 KB 且只允许 Viewer；授权绑定调用者与具体 KB/租户，并继续校验 API key 知识库 allow-list。`WithExecutionTenant` 改变查询执行的租户上下文，**不能等同有权读取来源租户全部 KB 或拥有修改权限**。

## 机制与边界

例子：用户让 Agent 汇总一个指定知识库并写出报告。首轮模型可调用 `search_knowledge`，下一轮收到检索工具结果并决定继续查询还是输出；若模型又提出两个读取工具再提出写文件工具，两个读取可并发，写文件需等读取结束，写后再继续。倘若模型回包恰好在工具参数 JSON 中间截断，本轮任何工具都不执行，模型在下一轮收到每个调用的“参数未完成，请重发”结果，避免生成半份报告。若用户点停止，`ctx` 取消时不应调用普通的“轮次已耗尽”兜底覆盖此前输出；某些已完成工具结果可被尝试整理，但函数仍把取消向上返回。

上下文预算不是只截取最近 N 条消息：历史读取用模型窗口给 token 预算，还要恢复压缩 checkpoint 和真实的工具调用轨迹；执行中根据估算/实际 usage 校准，接近阈值总结较老的轮次，避免溢出；最近尾部过大时才裁剪工具返回。压缩后的摘要不应宣称无损，checkpoint 也不是“可以让无限上下文永久准确恢复”。授权同样是多层：handler 先授权共享 Agent 身份，服务再生成这个 Agent 的检索范围，工具注册/执行必须沿用调用者绑定的 grant；仅有模型提出“去查另一个 KB”不能越过 `HasKBGrant` 与 API-key 限制。

## 需要懂什么

ReAct 里的“观察”指把工具实际结果写回模型可见消息，而非只显示前端日志；“分析”判断是否自然停止、是否需要工具、是否触发重试或挂起。`MaxIterations` 防无限循环；`ctx` 取消处理用户停止；`minFreedFraction=20` 防压缩经济性倒挂；一次强制窗口恢复处理估计误差。并发工具的权限要考虑真实副作用：标成可并发的工具才允许一起跑，读写边界不能靠 LLM 输出顺序侥幸保证。共享 Agent 能执行来源租户的数据查询与“有资格读取每个来源 KB”是两个不同判断。

## 需要记住什么

面试复述四句话：**AgentQA 从 DB 按 token 预算加载历史；Engine 有界 ReAct，观察工具结果再回模型；上下文超阈值先压缩，收益不足 5% 跳过同尺寸反复压缩，必要时裁剪/一次溢出恢复；工具截断不执行，并发读限 8、写有屏障，共享 Agent 仅被授予配置 KB 的受限读权限**。不要把 C08 的单次 RAG pipeline 当成这里的多轮工具循环。展开设计取舍见[Q6](../WeKnora/面经.md#q6-智能体连续执行时如何约束上下文与工具调用的权限)，租户边界见[Q2](../WeKnora/面经.md#q2-如何让普通页面与嵌入页面显示受保护内容但不混淆权限)。
