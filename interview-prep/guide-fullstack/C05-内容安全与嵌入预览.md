## 本课重点

知识库文件、聊天 Markdown、模型生成的 HTML 和嵌入访客的对话都可能包含外部内容。安全不能只说“调用 DOMPurify”：既要限定哪些内容能作为 HTML/脚本执行，也要决定 `resource://` 文件由哪个身份代理获取、图片 blob 缓存是否跨鉴权上下文混用、嵌入 iframe 与普通登录态的凭据是否串线。本课顺着渲染前清理 → 受保护资源水合 → 文件预览 → Embed 单独入口与服务端门禁，建立前端展示边界与后端真正授权的区别。

## 主链与职责

聊天/文档 Markdown 先变 HTML 再经过白名单清理；带存储协议的图片不会直接放带 token 的 URL，而是先留透明占位和 `data-protected-src`，确定当前访问上下文后再向 `/files`、KB、消息或 Embed 文件代理发送带 Header 的 GET，收到 blob 才更新 DOM。文档预览按来源选择文件获取接口和展示类型：普通 KB 文件/聊天附件的 HTML 只显示源代码，允许脚本的生成 artifact HTML 仅进入独立的 sandbox iframe。Embed 使用单独 Vue 入口、独立 Embed token 与会话签名；服务端对 channel、token、来源与额度逐级验证。浏览器执行上下文、凭据与资源边界需要同时成立，任何“前端隐藏了链接”都不等于后端文件已授权。

## 源码阅读

1. **先清理输出。** 读 [`sanitizeWithSecurityHooks()` 和标签/属性白名单](../../frontend/src/utils/security.ts#L40-L101)：DOMPurify hook 在 `finally` 移除，避免一次渲染残留影响其他渲染；`sanitizeHTML()`、`sanitizeDocumentPreviewHTML()`、`sanitizeMarkdownHTML()` 各走其策略，清理抛错时退回转义纯文本，而非原样放行，见 [三条 sanitize 路径](../../frontend/src/utils/security.ts#L103-L185)。对存储图片，读 [`protectProviderImageSrcInHTML()`](../../frontend/src/utils/security.ts#L211-L253)：把 provider/storage 图片改为占位符或此前水合的 blob，保留受保护源路径供后续鉴权拉取。
2. **资源请求的鉴权平面。** 读 [`ProtectedFileAccessContext`、`resolveProtectedFileAccess()`](../../frontend/src/utils/protectedFileAccess.ts#L1-L91)：普通登录态 `/files`、跨租户知识库、聊天消息上下文与 Embed 访客代理分开；默认 Embed 平面不能被组件的 KB/message override 换成 Bearer 路径。读 [`buildProtectedFileRequest()`](../../frontend/src/utils/protectedFileAccess.ts#L109-L172)：登录态 Bearer 附已选 `X-Tenant-ID`，访客仅发 `Authorization: Embed ...`；缺 Embed token 时返回 null 待下次水合，而不是回退到错误身份代理。代理选路是客户端构造请求，服务端仍逐接口校验实际权限。
3. **水合与缓存。** 读 [`hydrateProtectedFileImages()`](../../frontend/src/utils/security.ts#L606-L724)：请求 key 是 `[requestURL,headers]`，包含凭据及目标空间；同 key 共享在途 Promise，404 只记录在该 key 下，失败有 5 秒冷却；单个 `<img>` 记录当前 key，迟到旧响应不覆盖新的授权结果。`clearProtectedFileFailureCache()` 可在流结束后重开尝试，见 [失败代际和缓存结构](../../frontend/src/utils/security.ts#L444-L511)。**另读源路径缓存的捷径**：[`buildProtectedImageTag()` 用 `protectedFileBySource.get(protectedSrc)`](../../frontend/src/utils/security.ts#L211-L231)；此处和已做鉴权请求的 key 设计不同，不应混为一谈。
4. **文件预览与隔离。** 读 [`getPreviewSourceKey()` 与 `allowsHtmlScriptPreview()`](../../frontend/src/components/document-preview.vue#L359-L399)：只有后端消息 artifact 来源获脚本预览模式；KB 上传、聊天附件保留 HTML 源码视图。读 [`loadPreview()` 的 MIME/格式嗅探和类型分流](../../frontend/src/components/document-preview.vue#L421-L525)：artifact HTML 的渲染副本由 [`buildHtmlPreview()`](../../frontend/src/utils/htmlPreview.ts#L56-L68) 包装，Markdown 图片补做鉴权水合，EPUB HTML 清理，PPTX 异步返回时核对来源及 active。实际隔离在 [HTML iframe 模板](../../frontend/src/components/document-preview.vue#L931-L945)：`sandbox="allow-scripts"`，没有 `allow-same-origin`，设置 `referrerpolicy="no-referrer"`；[cleanup()](../../frontend/src/components/document-preview.vue#L528-L553) 回收 blob/EPUB 对象 URL。脚本预览不是把任何上传 HTML 直接挂到应用 DOM。
5. **嵌入入口与服务端门禁。** 读 [`embed-main.ts` 单独 router 和应用](../../frontend/src/embed-main.ts#L1-L35) 及 [Vite 双 HTML 构建输入与 preload 过滤](../../frontend/vite.config.ts#L96-L139)：这是构建方案，不能在没有测量时声称降低了多少 KB 或改善了多少秒。读 [`getEmbedConfig()`、`createEmbedSession()` 的 Header](../../frontend/src/api/embed/index.ts#L284-L328)，[父窗口消息来源检查与已知 origin 固定](../../frontend/src/api/embed/index.ts#L458-L514)，[生成嵌入 URL 和代码片段](../../frontend/src/api/embed/index.ts#L573-L669)；最后核对后端 [`EmbedAuth()`](../../internal/middleware/embed_auth.go#L73-L175)、[`extractEmbedToken()`](../../internal/middleware/embed_auth.go#L179-L188)、[API 同源例外及跨源 allowlist](../../internal/middleware/embed_auth.go#L208-L237) 与 [HTML 页面的 `frame-ancestors` 响应策略](../../internal/router/routes_agent.go#L357-L416)。宿主能否嵌入由 HTML 响应 CSP 限制，而不是用 iframe 内 API 的 Origin 反推宿主；自定义反向代理也必须保留这条 CSP。

## 机制与边界

正常路径：嵌入访客从 host 获取 publish token 或交换得到 session token，经 `Authorization: Embed` 调 Embed 接口，签名会话通过 `X-Embed-Session` 传；服务端校验 channel/token、API 的同源请求或跨源允许列表，以及单 IP/整个频道分钟额度和频道日额度；宿主 iframe 是否允许加载另由 HTML 页面的 CSP `frame-ancestors` 约束，创建仅该频道所属 tenant 的 viewer 主体。浏览器端通过 Embed 文件代理获取图片，不能靠客户端组件误传 `knowledgeBase` override 就借用登录态。宿主与 iframe 的 `postMessage` 检查 `event.source === window.parent`、来源标识和 origin；未确定 origin 时可用 `*` 发非敏感 bootstrap/ready，但对话内容等敏感出站消息直接丢弃。URL 构造把 token 放 hash 避免通常随 HTTP 请求进入访问日志；注意 `parseEmbedTokenFromLocation()` 仍兼容读取 query token，**后端本身只接受 Authorization Header**，不要说所有前端路径都拒绝 query token。公开 iframe/widget 片段可见 publish token，安全模式片段改为集成方后端换短期 token 的端点示例，不能宣称部署时天然保密。

异常与风险路径：API 跨源请求未获允许会返回 403；频道无效、禁用或没有允许宿主时，iframe 页面策略接口可返回 403。若频道有效但宿主不在允许列表，HTML 响应仍可能是 HTTP 200，只是浏览器因 CSP `frame-ancestors` 阻止嵌入；不要把这当成 API Origin 403。限流返回 429，缺/错 token 返回 401；Origin 限制是额外门槛，不是凭据。HTML 清理失败会转义，artifact 以 opaque-origin iframe 执行脚本；但 `allow-scripts` 不是“脚本完全无网络能力”，隔离的重点是不给应用同源权限与 DOM。受保护资源水合的 request key 含当前 Header，可以防止迟到响应改写新请求的 DOM；**静态源码观察仍有一个待验证风险**：预水合渲染使用只按源 URL 索引的 `protectedFileBySource`，若同页切换身份/空间后相同 source URL 可指向不同可见资源，可能重用之前的 blob。这里没有做利用验证，不能写成已确认泄露；诊断时应针对同页身份变化检查该 source-only 快捷路径，而不是否定整个按 request key 的拉取设计。

## 需要懂什么

**XSS 防护是分层的。** 渲染 Markdown 的 `v-html` 之前清理标签、属性和危险链接；富 HTML 的脚本预览仅向符合来源条件的 artifact 开放，并限制到不带 `allow-same-origin` 的 iframe；不同于文本/Markdown 的普通净化，iframe 的脚本能力需要单独威胁建模。**文件访问有两种标识。** 原 `resource://` 是对象的业务地址，不包含“谁可读”；真正的代理 URL 和 Header 才包含访问作用域，后端检查会话、KB、消息或频道。**缓存键也是权限边界的一部分。** 失败/缺失及 blob 复用若不绑定身份和作用域，可能跨上下文制造错误显示；按请求键合并能保证同一授权请求复用，但额外的按源捷径也必须审查。构建代码分割只说明意图，性能效果应另测。

## 需要记住什么

- Markdown 清理与图片水合不同步：先安全占位，再按当前鉴权平面带 Header 拉资源；后端代理才是真正的文件读取权限检查。
- 上传 HTML 默认展示源码；生成 artifact 脚本只在 sandbox iframe 运行，没有 `allow-same-origin`；切换文件时回收局部 object URL。
- Embed 的 channel/token/origin/额度分层验证不等于普通用户 JWT；静态的 source-only blob 复用仅作待验证风险说明。对照 [Q2](../WeKnora/面经.md#q2-如何让普通页面与嵌入页面显示受保护内容但不混淆权限) 明确“已实现边界”与“尚未验证的风险”。
