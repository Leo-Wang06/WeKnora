# C08 动态问答流水线：从会话问题到可引用答案

> 课程性质：核心；目标掌握：看懂链路、理解机制、设计与表达。
> 返回：[导学](../WeKnora/导学.md)；前置：[C01 身份与租户边界](C01-身份与租户边界.md)、[C07 混合检索与重排](C07-混合检索与重排.md)；上一课：[C07](C07-混合检索与重排.md)；下一课：[C09 智能体循环与上下文预算](C09-智能体循环与上下文预算.md)。
> 对应：B5；[面经 Q5](../WeKnora/面经.md#q5-只有向量只有关键词或两路都有时检索和问答分别怎样变化)。源码基线：`d06733d4157736c0e0e7972d014f0f056d237bb0`；本课讲非 Agent 的 KnowledgeQA，Agent 路径另见 C09。

## 本课重点

用户在会话中提问不意味着每轮都跑检索：`KnowledgeQA` 先解析实际可访问的知识范围、聊天模型、租户与特性开关，然后按是否需要 RAG 组装阶段。标签限定的提问即便原始 KB/知识 ID 数组为空，也可能产生 `SearchTargets`，不能降级为纯聊天。纯聊天仅加载可选历史、记忆召回和流式生成；RAG 才追加问题理解、知识搜索、重排、融合、筛选及上下文入模。引用先于流式答案发出；用户取消必须先于“没搜到东西”的兜底分支处理。

## 主链与职责

`QARequest(会话、问题、标签、附件、Agent 覆盖项) → 获取/复用本轮租约 → resolveKnowledgeBases / resolveChatModelID / buildSearchTargets → ChatManage 持有 PipelineRequest、PipelineState、PipelineContext → 条件化 EventType 列表 → KnowledgeQAByEvent 逐阶段派发 Plugin → 流式插件开启模型流并通过 EventBus 推思考/答案/错误`。会话服务选路并维护本轮请求参数，事件管理器负责把某种事件派给注册插件，插件对同一个 `ChatManage` 读写阶段状态；向用户展示的事件由 `EventBus` 输出，不能把“内部阶段事件”当成客户端已经收到的答案。

## 源码阅读

1. [入口：`KnowledgeQA`](../../internal/application/service/session_knowledge_qa.go)：若入口没有 `TurnLeaseHeld`，先拒绝正在回退的会话发送，再持有 sandbox turn lease；HTTP 发送已拿租约则不重复拿。其后解析知识库/知识 ID、聊天模型和共享知识运行租户，`buildSearchTargets` 把普通 KB、指定知识、标签等请求统一成目标，并一次填入 `ChatManage` 的请求、状态和 EventBus/消息 ID。自定义 Agent 可覆盖提示词和检索参数，但这里仍是普通问答 pipeline，不是 C09 的工具循环。
2. [条件组装：`KnowledgeQA`](../../internal/application/service/session_knowledge_qa.go)：先算 `hasKB := types.HasKnowledgeRetrievalScope(searchTargets, knowledgeBaseIDs, knowledgeIDs)`，`needsRAG := hasKB || webSearchEnabled`，`hasHistory := chatManage.MaxRounds > 0`。没有 RAG 时要把用户图片文字描述（若聊天模型无视觉能力）、引用文本、附件合入 `UserContent`，阶段为条件 `LOAD_HISTORY` → `MEMORY_RECALL` → `CHAT_COMPLETION_STREAM`。有 RAG 时加 `QUERY_UNDERSTAND`、`CHUNK_SEARCH_PARALLEL`、`CHUNK_RERANK`、按需 `WEB_FETCH`、`CHUNK_MERGE`、`FILTER_TOP_K`、按需 `DATA_ANALYSIS`、`INTO_CHAT_MESSAGE`，最后流式生成。`WEB_FETCH` 的加入受网页搜索开关控制，数据分析看生效后的 `DataAnalysisEnabled`。
3. [插件协议：`EventManager.Register/Trigger`](../../internal/application/service/chat_pipeline/chat_pipeline.go)：插件通过 `ActivationEvents` 声明可处理的阶段，同一事件按注册顺序组成 `next()` 链；某阶段没有监听器时 `Trigger` 返回 `nil`。`PluginError` 带底层错误和阶段错误类型，`ErrSearchNothing` 与模型/搜索故障有不同语义。
4. [逐阶段执行：`KnowledgeQAByEvent`](../../internal/application/service/session_knowledge_qa.go)：遍历阶段、创建非流式阶段的 trace span，必要时聚合检索进度；进入 `CHAT_COMPLETION_STREAM` **之前**发送知识引用，因为等流完成后连接可能已经被 complete 事件关闭。每段完成后先检查 `ctx.Err()`，再处理 `ErrSearchNothing` 的兜底，最后返回真实阶段错误。搜索中途取消也可能表现为空结果，若先兜底就会把固定文本写进用户主动停止的消息。
5. [流式插件：`PluginChatCompletionStream.OnEvent`](../../internal/application/service/chat_pipeline/chat_completion_stream.go)：准备模型与消息，检查 EventBus 后调用 `ChatStream`；独立 goroutine 消费 `responseChan`，将 thinking 发 `EventAgentThought`，answer 发 `EventAgentFinalAnswer` 并用 `Done` 终结，模型错误发 `EventError`。收到取消或通道结束时冲刷解码器保留的资源引用片段，避免拆包造成引用丢失；重复完成事件被 `answerCompleted` 抑制。插件返回表示流已启动，**不是 goroutine 已把最后一个答案字节发完**。
6. [检索与重排插件](../../internal/application/service/chat_pipeline/search.go)、[重排插件](../../internal/application/service/chat_pipeline/rerank.go)：搜索先按模型空间分组，预先计算查询嵌入并在同组目标间复用，常规 KB 联合调用 `HybridSearch` 且 `SkipContextEnrichment: true`；缺失向量时仅对确有关键词索引的目标降级。`PluginRerank` 用配置的模型和阈值对候选重排，模型缺失或调用失败时保留检索顺序并记录诊断；它与 C07 的显式 `HybridSearchWithRerank` 不是同一个入口。

## 机制与边界

以用户只在对话中选择“某个标签”而没有直接选 KB ID 为例：解析作用域可生成带标签的 `SearchTargets`。若只检查原始 ID 数组，就会错误走纯聊天；本实现使用 `HasKnowledgeRetrievalScope` 检查统一目标，继续进入检索和证据入模。相反，用户完全没选知识范围且关闭联网搜索时，不做空转向量检索；附件与引用上下文需在纯聊分支自己并入内容，不能期待 RAG 的 `INTO_CHAT_MESSAGE` 补它们。这正是“动态”而非固定 10 个阶段的因果。

有历史不是“永久把全部会话带入模型”：`MaxRounds` 非正时 `LOAD_HISTORY` 不在阶段列表。问答与 Agent 都可能读会话，但边界和预算不同，不能把 C09 的 `LoadAgentHistory` 描述为此 pipeline 的历史加载器。标签和共享 KB 应在解析目标、租户与具体 KB 授权时约束，切换检索执行租户不是自动获得该租户全部知识；底层 `HybridSearch` 还对每个 KB 做权限验证。搜索不到结果可进入配置的 fallback；真实检索故障需要暴露错误；被用户主动取消返回 `ctx.Err()` 而不覆盖成兜底答案。模型流已经启动后，由异步事件通道传递后续结果与 `Done`，trace 中不为流式阶段建立会过早结束的阶段 span；对外是否完成以终结事件为准。

## 需要懂什么

`PipelineRequest` 是这轮输入与执行选项，`PipelineState` 保存改写查询与检索中间结果等过程状态，`PipelineContext` 持有事件输出和关联消息；插件复用同一份 `ChatManage`，因而顺序就是数据依赖。问题理解、召回、重排、结果合并和 prompt 组装不是同义词：前者改查询，召回找候选，重排调次序，合并/筛选控证据规模，入模决定模型能看到哪些材料。事件驱动在此指**有序事件列表驱动插件**，不是每个阶段都在独立消费队列；真正的流式输出通过模型通道+EventBus 异步发送。

## 需要记住什么

复述判定式：**`needsRAG = HasKnowledgeRetrievalScope(统一目标, 原 KB IDs, 原知识 IDs) || webSearchEnabled`**。纯聊天三类阶段：可选历史、记忆、流生成；RAG 在此基础上增加理解、搜索、重排、可选网页抓取、合并筛选和证据入模。引用先于答案流、取消先于无命中兜底、`KnowledgeQAByEvent` 返回不等于流式完成。检索原理见[C07](C07-混合检索与重排.md)；完整 RAG 口播见[Q5](../WeKnora/面经.md#q5-只有向量只有关键词或两路都有时检索和问答分别怎样变化)。
